## 1. Current architecture summary

```text
CLI / GitHub Action / MCP (STDIO)
        │
        ▼
 Discovery → Project detect → Agent adapters → Rule engine → Findings → Scores
        │                                              │
        │                                              ▼
        │                                    Safe Fix (allowlisted writers)
        │
        └──► Project Understanding → Project Brain → LocalBrainStore
                                                      └── brain-mcp (10 tools)
```

| Surface           | Entry                                 | Role today                                                           |
| ----------------- | ------------------------------------- | -------------------------------------------------------------------- |
| **CLI**           | `agentdoctor`                         | `scan` (default), `fix`, `verify`, `explain`, `doctor`, `brain-mcp`  |
| **GitHub Action** | `AgentDoctor Safety` (`action.yml`)   | Safety scan/verify + policy gates only (no Brain/MCP)                |
| **Library API**   | `@praneeth_54/agentdoctor`            | `scan`, `verify`, `buildFixPlan`, `applyFixPlan`, registries, policy |
| **Project Brain** | `.agentdoctor/project-brain/`         | Deterministic local understanding + snapshots/deltas                 |
| **MCP**           | `agentdoctor brain-mcp --root <path>` | STDIO tools over loaded Brain                                        |

**Design invariants (must preserve):** local-first, deterministic core, no mandatory API keys, no secret printing, adapters over hardcoding, Safe Fix only for allowlisted official ignore/deny targets.

**Roadmap conflict (explicit):** `ROADMAP.md` marks dashboards/SaaS as non-goals and CI/PR Brain / optional AI as exploratory. The mega-feature request below **conflicts** with that product charter unless you approve a deliberate ROADMAP revision.

## 4. Proposed architecture (if approved)

Keep three pillars; add layers as **optional packages/commands**, not a rewrite of Safety:

```text
agentdoctor
├── safety/          (existing scan·fix·verify·action) — preserve APIs
├── brain/           (existing understanding + store) — add CLI façade + search
├── changes/         (NEW: git + finding delta orchestration)
├── context-health/  (NEW/EXTENDED: instruction conflict rules)
├── secrets/         (NEW: opt-in content hygiene, redacted reports)
├── fix/             (EXTEND: backup/undo/audit; keep allowlist)
├── monorepo/        (EXTEND: package targeting)
├── baseline/        (EXTEND: named baselines + compare)
├── github/          (NEW optional: PR analysis behind auth)
├── dashboard/       (NEW optional: local static/read-only UI — ONLY if ROADMAP revised)
├── plugins/         (NEW: typed extension points + sandbox policy)
└── local-ai/        (NEW optional: providers; core never depends on it)
```

**Data models (new or extended):**

- Keep `ProjectBrain` / snapshot schema; bump brain schema only with migrations
- New: `ChangeReport`, `ContextHealthReport`, `SecretFinding` (redacted), `FixAuditEntry`, `BaselineRecord`, `PrAnalysisReport`
- JSON schemas under `docs/schemas/` or `src/schemas/` with compatibility tests

**CLI sketch (illustrative — final names TBD):**

```text
agentdoctor brain <init|status|inspect|snapshot|history|search|rebuild|export|import>
agentdoctor changes [--since] [--compare] [--impact] [--findings]
agentdoctor context-health
agentdoctor secrets scan
agentdoctor fix … (existing + --backup / undo)
agentdoctor baseline <create|list|show|compare|delete>
agentdoctor monorepo <list|scan>
agentdoctor pr analyze …   # optional
agentdoctor dashboard …    # optional, if approved
```

Preserve all current commands and exit codes (`docs/reference/exit-codes.md`, `docs/reference/compatibility.md`).

## 6. Risks and limitations

| Risk                                                           | Mitigation                                                                            |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Scope explosion / unshippable 1.2.0                            | **Approve a sliced release train** (below)                                            |
| ROADMAP / product identity break (dashboard, cloud-ish PR bot) | Explicit ROADMAP revision before building                                             |
| Secret content scanning false positives + privacy              | Opt-in; redaction; never print secrets; document limits                               |
| Dependency “impact” claims without evidence                    | Emit UNKNOWN; never invent edges                                                      |
| Multi-writer Fix atomicity                                     | Document limitation; improve backup/undo rather than fake transactions                |
| Plugin arbitrary code                                          | Deny-by-default; signed/allowlisted plugins or in-process only with capability tokens |
| Local AI non-determinism                                       | Optional; label outputs; core tests never require AI                                  |
| Breaking CLI/JSON                                              | Additive commands; schema version fields; compatibility tests                         |
| Uncommitted Unreleased adapters already large                  | Land that slice first before mega-features                                            |

## 7. Test strategy

Reuse existing gates: `npm run verify` (= typecheck + lint + format:check + test + build), plus `verify:mcp`, `verify:project-brain` as relevant.

| Layer       | Approach                                                        |
| ----------- | --------------------------------------------------------------- |
| Unit        | Detectors, rules, redaction, fix preflight, baselines           |
| Integration | CLI subprocess tests (`tests/integration/cli.test.ts` pattern)  |
| MCP         | Existing `tests/unit/mcp/**` + new tools                        |
| Security    | Symlink/path fixtures; secret redaction never asserts plaintext |
| Git changes | Temp git repos in tests; no network                             |
| GitHub PR   | Mock HTTP; never real tokens in CI                              |
| Dashboard   | API contract tests; no browser cloud                            |
| Plugins     | Hostile plugin isolation tests                                  |
| Platforms   | Keep Ubuntu/Windows CI; path cases in unit tests                |

Do not delete/weaken tests to pass. Do not claim cross-OS without CI evidence.

## 11. Security considerations (plan-level)

- Preserve: no secret printing; MCP redaction; Action path containment; Fix allowlist + symlink/dir refusal
- New secret scanners must redact; distinguish tracked/untracked; document false-positive limits
- Plugins must not get unrestricted FS/network without explicit grants
- GitHub tokens never logged; local-only mode without credentials
- Dashboard read-only by default

## 12. Backward-compatibility strategy

- Keep `scan` / `fix` / `verify` / `explain` / `doctor` / `brain-mcp` behavior
- Additive CLI subcommands only
- JSON: additive fields + `schemaVersion` where new report types appear
- Action: do not change inputs without compatibility notes; bump Action tag only on human release
- Package remains `1.1.1` until implementation of the **approved** slice is complete and you authorize version bump
